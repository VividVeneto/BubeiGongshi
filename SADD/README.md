## 📋 本次修订

面向 Windows 和 Android 的公式背诵、编辑、计算和手写/照片识别软件，预留 HarmonyOS 接口。v4 依据 v3 校核意见与甲方澄清（以不背单词为原型，只需功能近似）修订：

- 背诵闭环改为功能近似不背单词的分组学习、客观作答、错题重现、组后默写与 FSRS 排程，并补回学习统计与计划；
- 量纲类型引入多态，补充计算链、记号方案与常数集；
- 同步、加密、GC 与识别状态机归入 Rust 无 I/O 核心，确定单一绑定面与鸿蒙验证路线；
- 补齐 Envelope 的 AAD 字段、本机解锁、设备配对、加密快照与合规门禁；
- 考研范围按数一、数二、数三分别建矩阵，冻结内容基线并更正开源许可结论；
- 识别指标改为分任务口径，新增忠实转写、判分、多态等验收。

当前仓库交付的是架构文档，尚无应用实现；性能、安全与识别质量数字为验收目标，不能视为实测结论。

## 🧪 交付与检查

- 运行 `node tools/verify-sadd.mjs` 检查标题与围栏、本地链接、禁用的行号引用、图的无障碍字段、来源样例、需求与验收 ID 引用以及 YOLO 主线守卫。它不运行应用测试，也不证明图形已视觉渲染。
- 14、`resources/feature-code-map.json`、`功能代码映射图.html` 与 `diagrams/*.svg` 由 `python tools/generate-feature-map.py` 生成；修改 10–13 后重新生成，并用 `--check` 确认无漂移。
- 开源资源完成一次实际试摄入：三条物理公式，固定来源版本/行/hash 与 BSD-3-Clause 许可；样例属于研究输入，尚未发布课程包。
- YOLO 详细预案仅位于独立分支 `codex/exp-yolo-recognizer`；主线不增加 YOLO 实现、模型和运行时依赖。

## 🔧 维护规则
