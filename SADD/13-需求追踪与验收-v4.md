## 📋 追踪规则与当前状态

- 本文件是需求追踪与验收的唯一出处：性能、识别、判分、内容质量与运维告警的数值目标只在这里定义，[10](10-软件架构设计-v4.md)、[11](11-数据安全同步与识别生命周期-v4.md)、[12](12-资源包内容与开源资源调查-v4.md) 只定义机制与口径。
- 当前状态：仓库只有架构文档，没有应用源码，未执行 Rust/Flutter 编译、模型推理、真机性能或渗透测试。下表 R、H、A 行全部为“设计覆盖，待实现验收”，全部 T- 项为“未执行”。不得把文档检查通过写成功能已达标。
- 验收状态取值：未执行、通过、失败、豁免。豁免须由对应负责人具名接受，写明理由与到期里程碑；性能与识别门槛的调整走 ADR（登记在 [09](09-架构决策与评审记录-v4.md)），不得改变测量口径。
- 编号：R01–R31 为本次原文需求，H01、H02 为历史扩展，A01–A04 为需求架构约束。A01–A04 与 09 的复审缺陷 RV-01–RV-17 无关（v3 复审缺陷曾用 A 编号，v4 已改名）。R04 的功能近似子项 R04.a–R04.j 定义在 [00](00-需求基线与文档效力-v4.md) §功能近似条款（R04 子项）。v2 与 v4 的需求编号同号异义，引用 v2 编号写成“v2:R17”，逐条对照见 §附录：v2 → v4 需求编号对照。
- 同一验收族有多行时用子编号（如 T-GC-01–T-GC-03）；其他文档引用族编号（如 T-GC）即指该族全部子项。
- 判定“通过”必须附 §本次文档检查与后续记录 中的结果记录；缺样本量、分层或阈值版本的记录按“未执行”处理。

### 识别质量指标与定值规则

语料要求：≥1500 条表达式样本，覆盖 ≥500 条不同公式，来自 ≥50 位书写人；来源分墨迹、拍照、截图，各 ≥300 条；复杂度分三档，各 ≥300 条——L1 为单行、无二维结构（如 F = ma），L2 含分式、上下标或根式，L3 含积分、求和、矩阵或三层以上嵌套；实拍子集中阴影、弱光、倾斜、模糊、纸张底纹各 ≥50 条。评测与训练的书写人不重叠，采集授权与去标识按 12 §模型、许可与供应链门禁 执行。

| 指标 | 定义 | 门槛 |
| --- | --- | --- |
| ExpRate | 规范化 LaTeX 记号序列与标注完全一致的比例 | M0 基线后定值（00 D-07） |
| ≤1、≤2 处错误率 | 记号序列编辑距离不超过 1、2 的比例 | M0 基线后定值 |
| 符号级混淆 | ν/v、1/l、×/x、负号与分数线等易混符号对的混淆率 | M0 基线后定值，单列报告 |
| 查找模式 Top-k | 库内检索 Top-1、Top-5 命中率 | M0 基线后定值 |
| 作答模式误纠正率 | 见 T-FIDELITY | ≤1%（已定） |
| 纠错成本 | 每式修正次数与修正耗时的中位数与 P90 | M0 基线后定值 |
| 时延与资源 | 见 §可复现性能预算 | 已定 |

公开参考（不作门槛）：PosFormer 在 CROHME 2014/2016/2019 上的 ExpRate 为 62.68%/61.03%/64.97%，在 HME100K 上为 69.51%，≤2 处错误率约 85%–91%；这是服务端规模模型的结果，移动端本地模型预计更低（来源见 12 §核实来源与访问记录 S28）。

定值规则：M0 用候选后端在冻结语料上测得各分层基线，按分层写出门槛，经 ADR 由需求负责人接受；门槛不得低于所选后端 M0 实测值减去其 95% 置信区间半宽。定值后只能经 ADR 调整，不得改变口径。云后端与本地后端分别定值，发布时至少一种后端达标（00 D-13）。

### 服务端监控告警阈值

指标范围见 10 §服务端最小部署；只采集运行指标，不含公式、图片或用户内容。

| 指标 | 告警条件 |
| --- | --- |

| UNKNOWN 终态占比 | 1 小时内超过 2% |

云识别端到端 P50 ≤5 s、P95 ≤15 s；排队时延与供应商时延分别记录，不计入本地预算。

能耗：不设常驻学习服务，不做周期性网络轮询；空闲时除每日一次本地提醒外没有定时唤醒。M2、M5 用 Battery Historian（Android）与 powercfg /energy（Windows）记录“典型学习 30 分钟”与“单次本地识别”两个场景，M2 结果作为回归基线；M5 同场景能耗比 M2 上升超过 20% 判为失败，须修复或经 ADR 接受。

体积上限放宽的理由：v2 定为 45 MiB（Android）与 70 MiB（Windows）。v4 的主包需要容纳一个原生推理运行时（二选一，见 10 §识别后端）、SQLCipher、Flutter 引擎与 bootstrap 字体，因此放宽到 70 MiB 与 90 MiB。放宽的是上限而不是目标：M0 登记各组成部分的体积，若实测仍不超过 45 MiB 与 70 MiB，则以实测值加 10% 作为此后的回归上限。

### 可维护性阈值

10 §错误码与可维护性度量 规定度量项与工具，本节给出阈值。硬性项在 CI 中失败即阻断合并；趋势项每个里程碑报告一次。

| 度量 | 阈值 | 性质 |
| --- | --- | --- |
| 依赖方向违例（依赖图越界） | 0 | 硬性 |
| 错误码注册表与 Rust、Dart、ArkTS 生成物的漂移 | 0 | 硬性 |
| 未经契约评审的 ABI 与绑定产物差异 | 0 | 硬性 |
| missing_docs 与 public_member_api_docs 告警 | 0 | 硬性 |
| unsafe 块 | fml-core、fml-study、fml-crypto、fml-sync、fml-store、fml-assets 为 0（forbid(unsafe_code)）；fml-ffi 与 fml-recognition 每块带 SAFETY 注释，新增须安全负责人批准 | 硬性 |
| 依赖漏洞与许可证扫描 | 无未处理的高危漏洞与不兼容许可证；新依赖须登记许可证与用途 | 硬性 |
| 圈复杂度 | 新增或修改的函数 ≤15；存量中超过 25 的函数数量不增加 | 趋势 |
| 函数长度 | ≤80 行（不含空行与注释，生成代码除外） | 趋势 |
| FFI 面 | 导出函数与 DTO 数量每个里程碑报告；单个里程碑增长超过 10% 须经契约评审 | 趋势 |
| 核心 crate 行覆盖率 | fml-core、fml-study、fml-crypto、fml-sync、fml-store ≥80%；单个 PR 下降超过 2 个百分点须说明 | 趋势 |

未来的 CI 至少包括：格式与 lint，单元与属性测试，FFI 契约测试，冻结语法与量纲回归（含本文的正反例集），存储迁移与故障注入，同步网关的权限与幂等，资源包安全，依赖漏洞与许可证，Flutter 分析与双端构建，依赖图越界检查，ABI 与绑定产物差异，公共 API 文档覆盖率。文档仓库不放空壳构建工作流。

## 🗂️ 本次文档检查与后续记录

`node tools/verify-sadd.mjs` 只检查文档结构、本地链接、编号与追踪、样例出处和 YOLO 守卫，不测试应用，也不证明任何指标达标。本文所有验收 ID 当前状态均为“未执行”。

实际验收按下面的模板逐条记录，未执行的项写 not_run，不得省略：

```json

  "status": "not_run",
  "milestone": "M0",
  "app_commit": "",
  "core_version": "",
  "resource_versions": {},
  "backend": "",
  "device": "",
  "dataset_or_fixture": "",
  "sample_size": 0,
  "strata": {},
  "threshold_version": "",
  "expected": "",
  "actual": "",
  "review_disagreement_rate": null,
  "evidence": [],
  "reviewer": "",
  "waiver": null

```

status 取值为 not_run、passed、failed、waived；waived 必须填写 waiver（owner、reason、due_milestone），由需求负责人或安全负责人具名接受。backend 用于区分识别与判分的后端版本；strata 记录分层结果，不能只填总体值；review_disagreement_rate 记录 T-CONTENT 与人工判例的双人审校分歧率。

4. T-CONTENT 的覆盖报告与第三人抽检记录已归档；
