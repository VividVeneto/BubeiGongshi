# 09 架构决策与评审记录 v4.0

_BubeiGongshi · 2026-10-18 · 架构决策记录（ADR）、历次评审缺陷及其处理_

---

## 📋 结论和评审边界

v4 保留 Flutter + Rust、本地优先、可插拔识别、签名资源包和追加式复习日志的方向，并按 v3 校核意见作五处结构性调整：

1. **学习范式**：背诵闭环改为功能近似不背单词的“分组学习 + 客观作答 + 错题重现 + 组后默写 + FSRS 排程”，主观四级自评降为辅助（ADR-008）。
2. **状态机归属**：同步合并、信封加解密、升级日志、GC、识别任务状态机从“共享 Dart 应用层”移入 Rust 无 I/O 核心；Dart 与将来的 ArkTS 只做界面、平台 I/O 与传输（ADR-009、ADR-010）。
3. **量纲类型**：TypeExpr 引入量纲变量与合一，通用定理可在严格量纲下表达（ADR-011）。
4. **安全相称性**：同步默认采用设备配对 + 恢复码，同步密语可选；补齐 Envelope 的 AAD 字段与本机解锁因素（ADR-012，11）。
5. **内容与合规**：内容以自编为主、开源只作校验（ADR-014）；面向含未成年人的境内发行设合规门禁（11、13）。

当前没有应用源码，无法验证真实内存、识别准确率或安全性；本文列出设计决策、风险与开发门槛，不作“无漏洞”的保证。评审依据见 [需求基线](00-需求基线与文档效力-v4.md)；v3 校核意见全文与 v2 文档见 [历史归档](历史归档.md)。

## 🏗️ 架构决策（ADR）

| ADR | 状态 | 决策 | 备选与代价 | 重新评估条件 |
| --- | --- | --- | --- | --- |
| ADR-001 | 生效（v4 修订） | Flutter 双端 UI + Rust 无 I/O 核心 | 全 Dart 更简单但鸿蒙需重写核心；双原生 UI 成本高；承担一次绑定工具链成本 | 团队无法维护 Rust/FFI，或 M0 绑定性能原型不通过 |
| ADR-002 | 生效 | 源码/模板编辑 + `FormulaView` 渲染端口；移动端提供公式模板键盘 | 不把自研数学排版作为 MVP 前置；flutter_math_fork 0.7.4 自 2025-05-21 无新版本，须封装在端口后并准备替换（10 §编辑器、公式库和学习流程） | 成熟库无法覆盖冻结语法，或维护停滞影响安全修复 |
| ADR-003 | 生效 | 模块化单体后端，托管或自建 OIDC 身份 | 不从微服务、消息集群起步；登录方式与身份提供方见 00 D-14 | 配额/队列指标证明有独立扩容需求 |
| ADR-004 | 生效（由 ADR-012 修订） | 私有同步 E2EE，本机库密钥不上云 | 需独立恢复流程；云识别图像不在 E2EE 边界 | 安全评审发现可用性/恢复问题，须公开修改保证范围 |
| ADR-005 | 生效 | 签名公开资源包，按需内容/模型 | 首装带 bootstrap；公开内容不额外加密；模型权重许可单独审查 | 有受限商业资源需另做授权设计 |
| ADR-006 | 生效 | 识别历史严格 N，默认 5、范围 0–100，失败与取消计入 | 不允许固定项绕过；另存附件须用户明确操作；口径待 00 D-15 确认 | 甲方明确更改计数口径 |
| ADR-007 | 生效（v4 修订） | 识别后端可插拔；云识别与本地模型分别验收、并行推进 | 本地模型按原文“预留”（00 D-13）；不能用 YOLO 检测替代公式识别；作答模式强制忠实转写 | 真实数据说明端侧成本不满足设备目标 |
| ADR-008 | 新增 | 学习范式：功能近似不背单词，客观判定为主、自评为辅 | 选择题与默写结果自动映射 FSRS 评分，用户可“记错了/申诉改判”并留痕；推导、证明、长公式保留自评。代价：需判分引擎、干扰项生成与人工审校 | 用户研究显示客观题干扰项质量不足或判分误判率超过 13 的阈值 |
| ADR-009 | 新增 | Rust sans-I/O 核心承载状态机：fml-core、fml-study、fml-store、fml-assets、fml-recognition、fml-sync、fml-crypto，经 fml-ffi 暴露 | 核心只接收事件、返回动作（网络、文件、计时器由宿主执行）；Dart/ArkTS 只做 UI、平台 I/O 与传输。代价：FFI 面变大，需要事件/动作 DTO 契约 | 鸿蒙路线放弃或 M0 证明 FFI 往返开销不可接受 |
| ADR-010 | 新增 | 单一绑定面：M0 在 flutter_rust_bridge 与手写 C ABI 中二选一作为 Dart 唯一绑定；C ABI 头文件保留给鸿蒙 NAPI | 短操作（解析、量纲，P95 ≤30 ms）同步调用；长任务（识别、同步批处理）以完成回调（Dart NativePort / NAPI 线程安全函数）通知，不轮询；DTO 版本化 | 选定工具链无法生成稳定 ABI 或不支持目标平台 |
| ADR-011 | 新增 | 量纲多态：TypeExpr 支持量纲变量（∀D）与合一；Unknown 不等于多态；纯数学式按 math_kind 类型检查 | 牛顿–莱布尼茨、泰勒、导数定义等通用定理可 Verified；代价：类型检查器复杂度上升，需正反例测试集（T-POLY） | 用户研究显示多态提示难以理解，或检查器性能超出 10 的预算 |
| ADR-012 | 新增（修订 ADR-004） | E2EE 相称性：默认设备配对 + 恢复码解锁账户根密钥，同步密语可选；本机解锁默认系统级 + 可选应用锁 | 学生与未成年人难以保管三种秘密；代价：设备配对需要已登录设备在场，丢失全部设备时只能用恢复码 | 安全评审或用户研究要求默认密语 |
| ADR-013 | 新增 | 鸿蒙路线：M0 同时验证 Flutter 鸿蒙移植与 ArkTS 原生 UI + NAPI 调用 C ABI，按结果定 | HarmonyOS NEXT 不运行 APK；两条路线都复用 Rust 核心。代价：M0 多一条验证线 | 官方或社区移植成熟度变化 |
| ADR-014 | 新增 | 内容来源以自编为主；开源库只作 Q-ID 对齐、交叉校验与单元测试；非商业许可内容（如 OpenStax CC BY-NC-SA 4.0、MathWriting）不进入发行包 | 自编需人力（12 §规模与人力）；双人审校 | 获得商业授权的教材或题库 |

这些为架构层面已选择的方案。具体渲染器、绑定工具、模型、身份服务和密码库须在 M0 原型中记录锁定版本和证据，不能把“采用成熟库”当作质量已证明。新增 ADR 使用以下模板：背景、决策、备选、后果、验证证据、重新评估条件、关联需求与测试 ID。

## 🧪 必须先完成的工程验证（M0）

1. **绑定面**：两端经同一绑定（ADR-010）调用解析、量纲、求值、FSRS、判分；验证跨端结果一致、取消、内存所有权、错误协议、短操作同步路径 P95 与回调通知。
2. **鸿蒙双路线**：Rust 核心交叉编译到 OpenHarmony 目标，Flutter 鸿蒙移植与 ArkTS + NAPI 各跑通一条“解析 + 量纲 + 渲染”纵切（ADR-013，T-OHOS）。
3. **量纲多态与判分原型**：用 13 的正反例集验证 TypeExpr 合一（T-POLY）与数学等价判分（T-GRADE）的误判率。
4. **渲染与输入**：至少 100 个冻结语法代表式验证渲染器覆盖、字体包加载、数学朗读与移动端模板键盘可用性（T-USABILITY）。
5. **识别**：登记训练数据/权重许可（12）；低配 Android 测本地模型质量、峰值内存；作答模式的忠实转写（T-FIDELITY）。
6. **安全与同步**：按 11 演练新设备恢复、设备配对、游客升级崩溃与合并到已有账户、并发同步删除、加密快照、历史 N=0/100、GC 中断、资源包恶意归档。
7. 以 13 的结果模板记录实际数据，未测试项明确为“未执行”。
