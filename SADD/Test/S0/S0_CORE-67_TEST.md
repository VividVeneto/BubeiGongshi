# CORE-67 测试方案

> 来源卡：[S0_CORE-67_基座.md](../../S0/S0_CORE-67_基座.md)（Dart DTO生成与漂移门禁）。本文件是该卡“验收标准”字段的全文，按卡片编程时直接引用；修改卡片功能时同步修改本文件，卡片因阶段变化改名时本文件同步改名（`S编号_卡号_TEST.md`）。工具按卡片中的引用把本文件自“**验收标准**”行起的内容原样拼回卡片，本行以上不拼回。

**验收标准**
- [R18][R19] 形状覆盖fixture（object、可选与nullable独立、enum、array、tuple、Diagnostic.args的typed map、三种union判别、公共与递归$ref）：生成文件含固定头“GENERATED CODE - DO NOT MODIFY BY HAND”、来源与generator文本常量且无时间戳；连续两次--write字节相同；DTO覆写==/hashCode按值比较、集合为不可修改视图、toString对sensitive_paths命中字段输出<redacted>。
- [R19] 数值与codec边界：int64映射int，decimal/uint64/int128/positive-int128映射String并保留原始十进制文本（含i64最小/最大值与2^127边界，不经double往返），base64映射Uint8List，number非有限值拒绝（以直接构造的类型图节点注入 NaN/Infinity：`jsonDecode` 不接受非标准 JSON，CORE-100 在入图前已拒绝，故该用例不依赖 schema 文本）；缺必填字段、类型不符、未知enum wire值、未知union判别、tuple长度或位置不符均抛FormatException；fromJson忽略未声明未知键、toJson只写声明字段。
- [R18][R19] 域推导与布局：op 第一段推导 <domain> 并写入 <out>/<domain>.g.dart；文件集是确定的 = <out>/types.g.dart 加每 ready op 一域，ast.schema.json 是纯 $ref 包装、不生成 ast.g.dart（断言生成目录内无该文件，且移走或改名 ast.schema.json 不改变文件集）；同域多 op 与共享类型按 (域, op 或 title) 字节序合并进同一文件；全局唯一 title 只生成一次且跨文件 import 可编译；生成目录之外的 schema 文件名不参与枚举。
- [R18][R19] 命名（冻结算法 ①～⑧ 的八个真实样例）：FormulaNode（field_const k）→ 类 FormulaNode、分支 FormulaNodeSymbol/FormulaNodeNumber/FormulaNodeUnit…；PathSeg（external_key 五分支）→ PathSegMoveTo/PathSegLineTo/PathSegQuadTo/PathSegCubicTo 与空载荷分支；MathKind（scalar_enum 与对象分支并存）→ MathKindReal/MathKindScalar 等；Diagnostic 的 severity → 内联 enum DiagnosticSeverity；Diagnostic 的 input_range → 具名 record DiagnosticInputRange；DisplayList 的 bounds → DisplayListNodeBounds；内联 object 与 union 分支大小写折叠同名时追加 Value；title 与 Dart 核心类型同名（如 String/Object）时追加 Value；仍冲突 → 退出 1、diagnostics 含 code=DTO_NAME_CONFLICT 并指出该分支。
- [R19] Diagnostic 交付：types.g.dart 的 Diagnostic 类 wire 名与 CORE-02 §诊断模型逐字一致（code/severity/node_path/input_range/args/recovery/needs_confirm，必填 code/severity/args/needs_confirm），severity 为 DiagnosticSeverity（error/warning/info），input_range 为 DiagnosticInputRange 即 (int,int) record 且长度不符抛 FormatException，args 为 Map<String,String> 不可修改视图且参与按值相等，未知 severity 字符串抛 FormatException，round-trip 后 ==/hashCode 成立；消费者 `typedef DiagnosticDto = Diagnostic;` 可直接编译，且生成文件里没有第二个 Diagnostic 类。
- [R18][R19] --check与--write语义分离：--check 不改动任何 Dart 文件（运行前后 sha256 相同），唯一写动作是 --report 指定的报告；--write 只写应存在文件集（先临时文件再原子 rename，不写报告文件，只在 stdout 打印摘要）；四态只看内容不看 mtime：应存在且缺失=missing（sha256 为 null）、字节相同=match、不同=drift、不应存在却满足生成物判定=stale（判定为头两行同时含 GENERATED 标记与 generator: CORE-67 v1）；手改生成文件 → drift 退 1；删除生成文件 → missing 退 1；在 <out> 放入同形状的生成物 → stale：--check 只报 stale 退 1 且不删，--write 删除并在 stdout 列名；<out> 应存在路径上的同名非生成文件 → 两种模式都报 DTO_HEADER_MISSING 退 1 且不删除；只动集合内文件与集合外生成物，不触碰目录外文件。
- [R19] 退出码与工具错误：一致且无error为0；漂移、CORE-100返回valid=false、required_stage范围内pending、release遇pending、命名冲突均为1；--check与--write同时给出或都不给出、--report不可写、清单读取失败、CORE-100抛SchemaToolError、未预期异常均为2，且不得从2降级为1或把1报成0。
- [R18][R19] 报告格式冻结：字段集为 version/mode/manifest/required_stage/release/ready/pending/skipped/files/diagnostics/exit；files 每项只有 path/status/sha256/expected_sha256 四键（expected_sha256 按类型图算、sha256 取磁盘内容、missing 与 stale 时为 null），按 path 字节序；skipped 按 op；diagnostics 每项只有 severity/code/op/file/pointer/message 六键并透传 CORE-100 的 schema Pointer，按 (file 或空串, code, op 或空串, message) 排序；同一输入两次运行报告逐字节相同，无时间戳、无绝对主机路径；本卡只产 DTO_SCHEMA_INVALID/DTO_PENDING_SKIP/DTO_NAME_CONFLICT/DTO_HEADER_MISSING 四码并原样透传 CORE-100 的 code，不写 contracts/errors/registry.yaml（DTO_* 是否登记归 CORE-02，未裁定）；pending 的 SKIP 行来自 CORE-100 的 info 诊断，既不计失败也不记为通过。
- [R18][R19] 阶段与pending：--required-stage S2且stage≤S2全ready时退出0；把S2内一条改为pending则为1并出现在diagnostics；仅有S3～S6 pending时只进skipped且退出0；--release遇任意pending为1；pending不生成类型（生成文件中不含该op的类型）；对真实 contracts/dto/manifest.json 运行 --check：36 个 ready 全部产出期望文件、107 个 pending 全部列入 skipped；判定与退出码只由内容决定——生成目录为空时 files 全为 missing 且退出 1，--write 后未再改动时 files 全为 match 且退出 0（不接受“0 或 1 都算通过”的二选一），不宣称消费方已签认或业务 op 已实现。
- [R18][R19] 只消费类型图、不复制schema规则：以CORE-100替身返回构造好的SchemaBundle时，生成结果只由图与manifest决定；把原始schema文件移出可读路径而类型图仍有效时生成不变（证明未二次解析schema）；生成器不读SADD、不import CORE-56/CORE-03实现。
- [R19] CI接入与边界：本卡只提交 tools/ci/manifest.json 的步骤条目片段（id=dto-drift、owner=CORE-67、argv 以 python tools/ci/gen_dto.py --check 开头且含 --report build/dto/drift.json、release_args 含 --release），由 CORE-41 合入其已冻结的 {version:1,steps:[{id,owner,argv,release_args?}]}，本卡不直接改写该文件、不引入反向依赖；用替身聚合器验证该步骤退出 1 映射为 fail、退出 2 映射为 error；fixture 的 manifest/schema 位于 tools/ci/tests/fixtures/dto/（fixture.manifest.json、fixture-echo.schema.json）并以 --manifest 显式指定，不写入 contracts/dto/。
