# CORE-77 测试方案

> 来源卡：[S1_CORE-77_引擎.md](../../core/S1_CORE-77_引擎.md)（量纲变量与合一）。本文件是该卡“验收标准”字段的全文，按卡片编程时直接引用；修改卡片功能时同步修改本文件，卡片因阶段变化改名时本文件同步改名（`S编号_卡号_TEST.md`）。工具按卡片中的引用把本文件自“**验收标准**”行起的内容原样拼回卡片，本行以上不拼回。

**验收标准**
- [R13] 单元：`unify(D_f·D_x, L²)`（`D_f` 编号小于 `D_x`）解得 `D_f = L²·D_x⁻¹`；`unify(D_f², L)` 解得 `D_f = L^(1/2)`；`unify(L, T)` 报 `DimConflict`；先 `unify(D_f, L)` 再 `unify(D_f, T)` 报 `DimConflict`；`unify(Angle, 无量纲)` 报 `DimConflict`；冲突后 `Subst` 与调用前 `==`。
- [R13] 溢出：`L^(i128::MAX)` 与 `L^1` 的 `mul`、`pow` 指数 `i128::MAX` 再乘 2、`unify(D, L^(i128::MIN))` 的取负倒数，分别返回 `UNIT_OVERFLOW`（unify 路径为 `Overflow`），且 `Subst` 不变。
- [R13] 属性（`proptest`，每项 ≥ 1000 例，固定种子可复现；生成：变量个数 0–4，指数分子 −6..6、分母 1..4，base 为 7 个基本维度的小整数指数）：`unify` 成功则 `resolve(a) == resolve(b)`；`unify(a, b)` 成功当且仅当 `unify(b, a)` 成功；重复 `unify` 后 `Subst ==` 不变（幂等）；同输入重复 100 次得到彼此 `==` 的 `Subst`；`bindings()` 右侧均不含已绑定变量；任何输入不 panic。
- [R13] 多态合一序列（本卡独立运行、字面输入，对应 CORE-09（下游说明，非契约）DX-05～DX-11 的规则展开）：变量按列出顺序用同一 `Subst` 的 `fresh` 分配，依次执行所列 `unify`；期望为全部调用成功、所列等式在 `resolve` 后成立、自由变量个数相符（度量：对所列全部变量各取 `resolve(var)` 后 `free_vars()` 的并集大小），判定与具体编号无关。DX-05 变量 f,x,F,C：`unify(f·x, F)`、`unify(F, C)` → `resolve(F) = resolve(f·x)`、`resolve(C) = resolve(F)`，自由变量 2；DX-06 变量 f,x,a,R：`unify(x, a)`、`unify(f, f·x^-1·x)`、`unify(f, f·x^-2·x^2)`、`unify(f, R)` → `resolve(a) = resolve(x)`、`resolve(R) = resolve(f)`，自由变量 2；DX-07 变量 f,x,a,b,ξ：`unify(a, x)`、`unify(b, x)`、`unify(ξ, x)`、`unify(b, a)`、`unify(f, f·x^-1·b)` → a、b、ξ、x 四者 `resolve` 相等，自由变量 2；DX-08（n = 3）变量 A,B：`unify((A·B)^3, A^3·B^3)` → 成功且 `bindings()` 为空，自由变量 2；DX-09（n = 3）变量 A：`unify(A·A^2, A^3)` → 成功且 `bindings()` 为空，自由变量 1；DX-10 变量 X,μ,σ,p：`unify(μ, X)`、`unify(X^2·σ^-2, 1)`、`unify(p, X^-1)`、`unify(p, σ^-1)` → `resolve(σ) = resolve(X)`、`resolve(p) = resolve(X)^-1`，自由变量 1；DX-11 变量 X,E,ε,V：`unify(E, X)`、`unify(ε, X)`、`unify(V, X^2)`、`unify(V·ε^-2, 1)` → `resolve(E) = resolve(ε) = resolve(X)`、`resolve(V) = resolve(X)^2`，自由变量 1。
- [R13] 跨来源协议：目标槽位类型 `L·D0` 与来源输出 `T·D0`（两份都自 D0 编号）不实例化直接 `unify` 报 `DimConflict`（伪冲突），按协议新建 `Subst` 并对两侧各调一次 `instantiate_types` 后 `unify` 成功；目标 `D0·D1^-1` 与来源 `D0` 不实例化时 `unify` 使 `resolve(D1)` 成为单位元（伪约束），按协议实例化后 D1 的对应新变量仍为自由变量；同一来源中 `D0` 出现在两个 `TypeExpr` 里，一次 `instantiate_types` 后映射到同一新变量，分两次调用则映射到两个不同变量；`instantiate*` 不改变指数、输出为规范形。
- [R13] 序列化与文本：`DimVar`、`DimExpr`（含 `vars` 非空）、`TypeExpr` 的 JSON 往返等价且与 `types.schema.json` 校验通过；乱序、零指数、同号重复的 `DimExpr` JSON 反序列化后等于规范形，同号合并溢出的 JSON 反序列化失败；`to_text` 对“文本化”所列四个黄金输入逐字节等于黄金文本。
- [R13] API 面单测：`DimExpr::one()` 的 `is_one`、`is_ground` 为真且 `to_text` 为 `1`；`from_base(L)` ground 且非 one；`var(D3)` 非 ground、`free_vars() == [D3]`；`inverse` 后再 `mul` 得 one；`free_vars` 升序去重；`Display` 与 `to_text` 逐字节一致；`resolve` 中途溢出返回 `UNIT_OVERFLOW`；`bindings()` 按变量升序；`instantiate(e) == instantiate_all(&[e])[0]`（同起点克隆比较）；`instantiate_types` 中 `dimension: None` 保持 None、其余字段原样；`DimConflict` 的 left/right 等于调用时两侧的 `resolve` 结果而非约去公共因子后的值。
- [R13] 外来变量：新建 `Subst` 后直接 `unify(var(DimVar(7)), L·var(DimVar(9)))` 成功，随后 `fresh()` 返回编号 ≥ 10；同样输入但 `unify` 失败时计数器与绑定都不变（`Subst ==` 调用前）；`resolve(var(DimVar(20)))` 原样返回且不改变后续 `fresh` 编号。属性测试的生成器只用 `fresh` 分配的变量。
