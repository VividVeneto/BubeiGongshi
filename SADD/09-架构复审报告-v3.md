# 09 架构复审报告 v3.0

_BubeiGongshi · 2026-10-18 · 对已有 v2 文档及本次需求的独立复审_

---

## 📋 结论和评审边界

保留 Flutter + Rust、本地优先、可插拔识别、签名资源包和追加式复习日志的方向。修订重点是把可实施契约补齐，并减少自研排版、密码协议和过度拆分模块的成本。当前没有应用源码，无法验证真实内存、识别准确率或安全性；本报告列出设计风险与开发门槛，不作“无漏洞”的保证。

评审依据见 [需求基线](00-需求基线与文档效力-v3.md)。旧文档提及而未提供的三份原始方案不作为已核实事实。

## 🛡️ 主要缺陷与修订

P0 表示对应功能发布前必须解决；P1 表示需在原型阶段验证；“定位”指 v2 现有文本，不推测原始文件内容。

| ID | 级别 | 定位与不足 | v3 修订及验证 |
| --- | --- | --- | --- |
| A01 | P0 | `02 §6.5` 与 `06 §7` 允许 Pin/Adopted 不受计数；0 次仍能保留历史 | 所有终态会话统一裁剪至 N；独立另存公式/附件显式告知；见 `11 §识别生命周期`、T-GC |
| A02 | P0 | `05 §2–3` “密码 KDF + 恢复码”不明，两者是否必须同时存在不清；把本机库密钥上传包装也会扩散历史可恢复性 | 随机账户根密钥，独立同步密语包装和随机恢复码包装二选一解锁；本机库密钥不上传；见 T-KEY |
| A03 | P0 | `01 A9` 声称删除包装密钥即可安全删除，未覆盖 WAL、备份和主密钥副本 | 明确逻辑删除与物理擦除边界；历史不进同步/备份，清理日志恢复，避免承诺闪存不可恢复；见 T-GC |

| A05 | P0 | `02 §4.3–4.4` Unknown 可被当作无量纲；温度点乘除一律禁止又与理想气体公式冲突 | Unknown 保持未知，草稿/已验证状态分离；绝对温度转换 Kelvin 后按物理角色参与乘除；角度为语义标签；见 T-DIM |

| A07 | P0 | `05 §5` 只有实体合并原则，缺少持久化游标、幂等、删除墓碑、旧设备复活防护 | 本地 outbox、服务端每账户序列、ACK 后推进游标、墓碑和 epoch 重建；见 T-SYNC |
| A08 | P0 | `02 §6.1` 游客缺少默认识别路径；可选模型未选型却将识别标为已覆盖 | 游客必须有通过许可/准确率/性能验收的本地模型包路径；未安装时给安装/手输入口，不声称已识别；见 T-OCR |
| A09 | P1 | `02 §4.2` Unicode/LaTeX “双射”不成立；多个写法和排版宏不能一一对应 | 原始输入保留、规范 LaTeX 与 AST 语义往返；显式 unsupported 与规范化差异；见 T-EDIT |
| A10 | P1 | `02 §5` M0 自研 Rust DisplayList 字形定位、字体排版和命中测试，工作量与轻量维护目标冲突 | 优先成熟 Flutter 数学渲染适配；Rust 控制语义；源文本/模板编辑先行；自研排版须单独 ADR 与原型证据 |
| A11 | P1 | `02 §2–3` 图示把领域层依赖到基础设施；同时禁止整个 crates 目录 HTTP，与基础设施职责混淆 | 领域无 I/O，应用端口向内，基础设施实现端口；六个初始边界足够，禁止规则仅约束纯核心 |
| A12 | P1 | `02 §8.3` 同济高数不能代替考研数学全范围 | 单列线代、概率统计，以及数一/二/三矩阵；未指定年份不宣称已覆盖现行大纲 |
| A13 | P1 | `06 §10` 启动/内存/云识别 <5s 无分位数、样本与机型；`07` 用 Top-3 评价检测器 | 规定基准设备、负载、P50/P95；模型检测与端到端识别分别评价，主线不写未测达标结论 |
| A14 | P1 | `04 §3` Windows 10 1809 被当作无条件支持基线；依赖与系统生命周期未区分 | 主支持 Windows 11 x64；Win10 22H2 仅按适用维护条件评估兼容；Flutter 支持不等于 OS 安全维护保证 |

## 🏗️ 取舍和新增决策

| ADR | 决策 | 备选与代价 | 重新评估条件 |
| --- | --- | --- | --- |
| ADR-001 | Flutter 双端 + Rust 纯领域核心 | 全 Dart 更简单但鸿蒙复用边界较弱；双原生 UI 成本高；承担一次绑定工具链成本 | 团队无法维护 Rust 或 FFI 性能原型不通过 |
| ADR-002 | 源码/模板编辑 + `FormulaView` 渲染端口 | 不把自研数学排版作为 MVP 前置；成熟渲染器也要验证白名单、字体资源和无障碍 | 必须精确所见即所得，或成熟库无法覆盖冻结语法 |
| ADR-003 | 单体模块化后端，托管身份认证 | 不从微服务、消息集群起步；登录认证与 E2EE 密语分离，增加一次密语管理 | 配额/队列指标证明有独立扩容需求 |
| ADR-004 | 私有同步 E2EE，本机密钥不上云 | 需独立恢复流程；云识别图像不在 E2EE 边界 | 安全评审发现可用性/恢复问题，必须公开修改保证范围 |
| ADR-005 | 签名公开资源包，按需内容/模型 | 首装带 bootstrap；公开内容不额外加密；模型权重许可单独审查 | 有受限商业资源需另做授权设计 |
| ADR-006 | 识别历史严格 N，默认 5、范围 0–100 | 不允许固定项绕过；另存附件须用户明确操作 | 甲方明确更改计数口径 |
| ADR-007 | 本地模型可插拔；云识别保留历史范围 | 模型许可和准确率是发布门槛；不能用 YOLO 检测直接替代公式识别 | 真实数据说明端侧成本不满足设备目标，需产品重新冻结能力范围 |

这些为架构层面已选择的方案。具体渲染器版本、模型、身份服务和密码库须在 M0 原型中记录锁定版本和证据，不能把“采用成熟库”当作质量已证明。

## 🧪 必须先完成的工程验证

1. 两端通过同一 FFI 调用解析、量纲、求值、FSRS；验证跨端结果、取消、内存所有权和错误协议。
2. 选择至少 100 个冻结语法代表式，验证成熟渲染器覆盖、字体包加载和数学朗读；不通过则缩小可承诺语法或另开排版 ADR。
3. 用低配 Android 验证本地识别模型的训练数据/权重许可、质量、峰值内存；没有可用模型不发布“游客手写识别已完成”。
4. 按 `11` 演练新设备恢复、游客升级崩溃、并发同步删除、历史 N=0/100、GC 中断、资源包恶意归档。
5. 以 `13` 的结果模板记录实际数据，未测试项明确为“未执行”。
