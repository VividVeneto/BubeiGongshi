# 附录 B：YOLO 识别预研 v5

> 版本：v5　修订日期：2026-10-18  
> 状态：实验预研，只在实验分支进行，不进入 `main` 分支。  
> 分支：`codex/exp-yolo-recognizer`  
> 目的：为甲方要求的“可能需要接入 YOLO 等类似的轻量化识别模型进行手写识别，请准备一个预备方案，不需要写入主分支”（R22）保留工程预案，不影响主线交付。  
> 效力：说明性。主线只承担两项义务：识别契约允许以新后端接入（CORE-29），以及 CI 证明主线零 YOLO 依赖（CORE-29、CORE-41）。

## B.1 定位

YOLO 不能直接把手写图片转换为 LaTeX 公式。它适合承担：

1. 公式区域检测。
2. 多公式切分。
3. 行与块结构定位。
4. 墨迹与图像中的噪声区域排除。
5. 给后续序列识别器提供更干净的输入。

因此，YOLO 只是识别管线中的检测组件，不是完整的手写公式识别器。主线的本地识别（CORE-35，编码器-解码器 HMER 模型）与云端识别（CORE-33、CORE-34）都不依赖它。

## B.2 实验分支结构

```text
codex/exp-yolo-recognizer/
  docs/                 # 实验设计、数据许可、评测结果
  data-tools/           # 样本转换、脱敏、切分工具
  models/               # 训练配置与模型说明，不提交大模型文件
  crates-exp/yolo/      # 实验适配 crate，实现 CORE-29 的 Recognizer trait，后端 ID "yolo-experiment"
  benchmark/            # 时延、内存、准确率脚本
```

约束：

- `main` 分支不得依赖 `crates-exp/yolo`，主线源码中不得出现 `yolo-experiment` 的注册调用（CORE-29 验收）。
- 实验模型不进入正式安装包；如需在设备上试用，按模型包格式（CORE-15、CORE-35）签名后离线导入。
- 训练数据不提交到仓库；大模型文件放外部对象存储，签名下载。
- 每个实施阶段（01 §2 的 S0～S7）结束时把 `main` 合入实验分支一次，防止分支腐烂；不对共享分支强制推送。
- 实验代码可以不满足主线复杂度门禁，但必须通过安全扫描。

## B.3 技术方案

### B.3.1 管线

```text
输入图片（CORE-30 预处理产物）
  → YOLO 公式区域检测
  → 区域透视/倾斜校正
  → 行与符号块切分
  → 轻量序列识别或规则后处理
  → LaTeX 候选（RawOutput）
  → CORE-31 统一后处理与校正
```

### B.3.2 模型选型

| 方案 | 优点 | 风险 | 结论 |
| --- | --- | --- | --- |
| YOLOv8 / YOLO11 nano | 体积小、检测快 | Ultralytics 实现采用 AGPL-3.0，闭源分发需商业授权；导出限制需核实 | 候选（许可未闭环前不得进入任何发布物） |
| YOLOX-Tiny | 部署简单，Apache-2.0 | 精度有限 | 候选 |
| NanoDet-Plus | 边缘端友好，Apache-2.0 | 数学区域样本不足 | 备选 |
| 传统连通域 + 形态学 | 无模型、可控 | 手写复杂场景弱 | 基线 |

必须同时实现传统算法基线，用于衡量 YOLO 的净收益。各项许可以附录 C 的核实记录为准。

### B.3.3 运行时

- 与 CORE-35 使用同一推理运行时（ONNX Runtime Mobile 或 MNN，M0 定案），不另引入运行时。
- 输入图片固定到 640–960 px。
- CPU 与 NNAPI/GPU delegate 分别测试，自动降级到 CPU。
- 识别结束释放运行时内存。

预算：

| 指标 | 门槛 |
| --- | --- |
| 模型体积 | < 15 MB（INT8） |
| 检测时延 | < 200 ms（中端 Android，P95） |
| 峰值内存 | < 80 MB |
| 常驻内存 | 0，按需加载 |
| 准确率 | 自有测试集端到端 Top-3 ≥ 85% 后再讨论合入；检测器指标与端到端指标分开报告 |

## B.4 数据与隐私

- 只使用许可清晰的公开数据集（附录 C 的数据集登记）与自采数据。
- 自采数据必须匿名化并获得书面授权。
- 不把用户图片自动作为训练数据。
- 训练集不提交仓库；数据目录记录来源、许可、脱敏方法。
- 云端训练环境不得保存与用户身份关联的原始图片。

## B.5 合入 `main` 的门槛

同时满足才允许评估合入，合入需新增 ADR 并经甲方同意（附录 A ADR-009）：

1. 与传统算法和现有本地识别后端（CORE-35）对比，准确率、时延、内存至少一项显著提升且无明显退化。
2. 中端 Android 真机通过性能与耗电测试（AND-12 口径）。
3. 模型包通过 Ed25519 签名和哈希校验（CORE-15）。
4. 训练与评测可复现。
5. 许可清单完整，且与闭源分发兼容。
6. 没有引入主分支运行时硬依赖。
7. 通过安全扫描和模糊测试。
8. 评审确认该能力解决实际用户问题（用户校正次数下降），而不是技术炫技。

## B.6 实验退出条件

出现以下情况应停止投入：

- 数学区域检测收益低于图像预处理（CORE-30）收益。
- 端侧时延或内存不达标。
- 训练数据或模型授权无法闭环。
- 与统一后处理（CORE-31）无法兼容。
- 用户校正次数未下降。
- 维护成本超过识别准确率收益。
